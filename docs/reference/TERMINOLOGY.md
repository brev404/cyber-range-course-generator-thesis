# Terminology: Course vs writeup

This document defines **project-generated output** vs **existing challenge inputs** and the simplified flow.

## Simplified flow

1. **Validate challenge structure** (Validator): Check that the challenge has the expected layout — source, solver, writeup (writeup.md or write-up.md etc.), description, attachments, etc. Some items may be missing; structure validation reports what is present.
2. **Pass challenge details to course generator** (Content Generation): Inputs are the challenge's **writeup** (author's writeup.md / write-up.md / solution.md), **description**, **solver** (solve.py etc.), **source**, **attachments** (whatever is present). The course generator produces a pedagogical **course**.
3. **Output**: The project writes the generated course to **course.md** in the same `cyberedu/write-up/` folder. The author's **writeup.md** is never overwritten.
4. **Validate the course** (Ranking): Pedagogical and technical reviewers evaluate the generated course (content in state / course.md).

## writeup (existing challenge — input)

- **writeup** = the author's or participant's solution explained. The existing challenge writeup: one of the files `writeup.md`, `write-up.md`, `solution.md` (see organize/parser for names), and the folder `write-up/`.
- Used for: **Validation** (e.g. "writeup exists", `MISSING_WRITEUP_MD`), **challenge structure** (CHALLENGE_STRUCTURE.md), and as **input** to the course generator (author's solution narrative).
- **Do not overwrite:** The project never writes to writeup.md; that file stays the author's.

## course (project-generated — output)

- **course** = the pedagogical course generated by this project: one per challenge. Expected output from a challenge.
- **Output file:** `cyberedu/write-up/course.md`. Optional: `solve_generated.py` for generated solver script.
- **State:** `state.generated_courses` (challenge_id → course text) and `state.generated_solve_scripts`.
- **Audience:** The course is written from the standpoint of a **student** who does **not** have access to the challenge source, the author's writeup, or the flag. It is a self-contained, logical explanation (discovery → reasoning → steps → solution); the author's writeup/solver are used only internally to ensure correctness.
- Use **"course"** or **"generated course"** when referring to this output.

## CyberEDU mapping

A **course** (this project's output) is placed in a **module** in CyberEDU. A **training** in CyberEDU contains multiple modules. So: challenge → course (our output) → module (CyberEDU) → training (CyberEDU).
